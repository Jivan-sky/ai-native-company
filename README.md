# ai-native-company

![ANC：一份真相源，三个消费面](./assets/cover.jpg)

> **把组织的协调能力，从人的职位上解绑，挂到系统上。**

一家公司里最贵的东西不是算力，是「这件事该找谁、凭什么、做到哪了」。
这些信息今天装在人的脑子里、聊天记录里、和被反复转述的口头约定里。
人一走、一休假、一忘，它就得重新问一遍 —— 而这笔成本从来没人记账。

ANC 把这件事搬进系统：**组织的事实写成文件，权限写成数据，动作留下痕迹。**
于是新人不必问人、Agent 不必猜、老板不必挨个问进度。

---

## 它解决的是什么

不是"帮你写代码"，也不是"帮你聊客服"。它解决的是三件反复发生的麻烦：

| 麻烦 | 今天的解法 | ANC 的解法 |
|---|---|---|
| 新人来了，一周都在问人 | 老同事带、文档找 | 真相源里就有"谁负责什么、资料在哪、能碰什么" |
| AI Agent 让它干活，它不知道边界 | 靠 prompt 约束 | 权限是数据，越界在门口就被拦下，被拦也留痕 |
| 出事了，查不出是谁批的 | 翻聊天记录 | 每一笔行使都有：谁、何时、依据哪条授权、原文在哪 |

判断这套东西成不成，只有一句话：

> **一个新人和一个 Agent，能不能不靠问人，拿到全部上下文、权限和工具，把活干完，并且有人能验证。**

完整口径在 [`SPEC.md`](./SPEC.md)。

---

## 它长什么样

三个面，同一份事实：

| 面 | 是什么 | 在哪 |
|---|---|---|
| **真相源** | 一家公司的组织事实：谁在做什么、数据在哪、谁能碰什么。全是文本文件，进 Git。 | `SPEC.md` + 客户自己的 vault |
| **接入面** | 一个单二进制 `anc`：初始化、装配、任务队列、审批、审计、作业、外部接入。 | `runtime/` |
| **观测面** | 一块只读看板 + 少量写动作：一屏一问题，每个数字都能点开看它怎么算、从哪来。 | `anc board serve` |

真相源只有一份，另外两个面都是它的派生视图 —— 改口径只改一处。

## 三条不许破的规矩

这三条决定了它跟"又一个 AI 工具"的区别。

**一、每个数字都要能回到原文。**
看板上的汇总数字，点开能看到它的公式、来源文件与行号、谁维护的、多久没更新。
算不出来的数字不上屏，宁可不画。

**二、权限是数据，不是代码里的 if。**
岗位能碰哪些模块、跨域能不能行使、这条授权有没有被撤回 —— 都在文件里，改文件就改权限。
判定在行使的那一刻做：撤了权就是不能用，过期就是过期，签发的人走了链就断。
判不出来的时候，结果是「无法判定」，**永远不是「放行」**。

**三、动客户的东西，按生产变更对待。**
预演只算不写 → 逐字段说清改了什么 → 写临时文件 → 读回来验一遍 → 备份旧版 → 原子换名。
任何一步失败，盘上什么都不变。停用不等于删除，历史留着。

## 谁在用它，用它做什么

- **一号位**：今天有没有事、该谁动手、有没有东西在烂。
- **业务负责人**：我的域里谁在跑什么、卡在哪、要不要我拍板。
- **一线**：接手一件事、办完、交给下一手，全程不用问"这该找谁"。
- **Agent**：被派活、拿上下文、在权限内动手、被拦时知道为什么。

## 怎么开始

```bash
cd runtime
bash dev/dev.sh all      # 宿主机不需要装 Go：fmt / vet / 测试 / 六目标交叉编译 / 烟测
bash dev/dev.sh board    # 起一个演示看板，地址打在终端上
```

从零建一份真相源：

```bash
anc init <目录> --client <客户名> --tier 1
anc org init <目录> --client <客户名> --id <ascii-id>
anc org check <目录>
```

## 结构

```
ai-native-company/
├─ SPEC.md          真相源：组织模型 · 四层两纵切 · 七连接件 · 三档可逆 · 判据
├─ assets/          封面与作者头像
├─ docs/            给实现读：上游四份实现视图的副本
├─ skill/           给 Agent 读：可单独安装的能力件
└─ runtime/         给机器跑：单二进制 + 只读看板
   ├─ DESIGN.md     运行层落地设计（决策在 §0，实测记录在 §7）
   ├─ docs/         计划、规格、决策台账、指标合同
   ├─ dev/          容器里的验证腿
   └─ testdata/     测试样本一处收着
```

**测试代码跟着包走，测试样本一处收着。** 前者是 Go 的语言约束，
后者是纪律：样本不进正式文件的目录，免得有人把它当数据读。

**开放问题不在仓库里。** 未定事项记在 [Issues](https://github.com/Jivan-sky/ai-native-company/issues)，
每条写清「要定什么 / 为什么没定 / 选项与建议 / 验收 / 卡住谁」。

## 它不做什么

- **不做第二套写口。** 装、审、接这些动作最终落回命令行语义，看板只在白名单上开几条写口。
- **不把客户的库搬过来。** 数据在客户库里，ANC 只连不搬；升级代码不碰那些库。
- **不假装有权限。** 没有真身份时，页面级可见性只是演示，能力判定默认关闭，页面上就写着这句话。
- **不承诺降本数字。** 提效是结果，不是卖点：先让"找谁、凭什么、做到哪"这件事有答案。
- **不替客户决定治理。** 谁有权发第一个权限、撤权什么时候生效，由客户定；我们只提供机制与默认值。
