# 三档账号走查（模拟）

> **这些账号是模拟的，行为也是我设定的。** 它不是可用性研究，它验证的是**系统的行为**：
> 哪一档能进哪一页、进不去时看到什么、能做的事全流程走不走得通。
> 真人怎么想、会不会用，只有真人能回答（PLAN §6 最后一条）。

## 走完发现两个真问题（都已修）

### 1. 要了没权限的标签，被静默换成第一个能看的

`xiaoli` 书签里有 `#/records?tab=audit`。原来的行为：页面正常显示「时间线」，一个字都不提审计。
**他会以为审计是空的** —— 这正是这个产品最不该犯的错（把「不给你看」显示成「没有」）。

改成：明确要了装不下的标签，就点名拒绝 —— 「「审计」对成员不开放。这一组里你能看的是：时间线。」

### 2. 「谁在点」填中文名，点完才被拒，而且填的「为什么」跟着丢了

后端要求 `by` 能当文件名（`timeline/<月>.<谁>.jsonl`），所以拒收中文名 —— 这规则是对的。
但用户是**填完、点完**才被告知，那一刻页面重画，刚写的「为什么这么批」没了。

改成：输入框下面边打边说规则，不合法立刻变红；提交前先校验，省一次往返。

## 端到端走通的一件真事

管理员 `laozhang` 批了 `member:bob 申请 trade 的权`：

| 动作 | 结果 |
|---|---|
| 点「同意」 | 回执「刚刚点头：同意（zhangwei）」 |
| 队列 | 2 → 1 |
| 时间线 | 22 → 23 条，新增 `prop-2026-1111-001 · done · member:bob 申请 trade 的权 —— 同意` |
| 审计 | 52 → 53 条 |
| 按人搜 | `#/timeline?by=zhangwei` 能搜到这一条 |

这一条链是整份走查里最有说服力的：**批准 → 落 timeline（按人可分文件）→ 落 audit → 按人搜得到。**

## 事实：4 个角色只有 3 种可见范围

超管与管理员在**只读**层面完全一致。差异本该出现在「改别人的权限」上 ——
那是写能力，看板没有写口（DECISIONS #1、#4）。所以现在切换超管/管理员，
除了右上角那个词，页面一模一样。这不假装。

## 已知缺口（不是这次修的）

- **待批对成员显示全部提案**：条目级过滤需要真身份（「张三只看该他批的」），现在是角色级。
- 团队负责人看不到「业务域」「运行」「审计」「沉淀」—— 这是他这个角色现在能看的下限，
  他要知道「我的 pipeline 什么时候跑」只能找管理员。这符合当前 GATES，但**可能不是你想要的**，
  需要你拍：负责人该不该看自己域的作业。
