# 看板 v3 规格（口述整理，待拍板）

> 来源：2026-11-11 口述。这里是**整理，不是发明** —— 你说了什么就写什么，
> 你没说的（比如「功效」到底怎么算）就留在「缺什么」里，不替你想。

## 一句话

看板是数据中台的**操作面**：一眼看见业务域的效率、谁的活卡在哪、资产沉到哪、系统哪里不健康；
并且**一切按组织层级隔离** —— 超管 > 管理员 > 团队负责人 > 成员，层层只管自己那一摊。

## 这一轮只做框架

原话：「我们现在只需要做出一个框架，然后真实的话，是会根据具体的业务状态、真实的组织架构去做适配。」

所以完成标准是：

1. 每一页有**真骨架**（布局、分区、交互位置），不是占位方块；
2. **不编数据**：没有真数据的曲线，宁可不画，也不画一条看起来像那么回事的线；
3. 缺的东西**一句话**写在页面上（不是一段说教）；
4. 能接现有 `/api/*` 的就接，接不上的写明依赖哪个议题。

## 先要定的一件事：「功效」

你说「不一定非常准确，统计口径也是多变的」—— 这是对的，所以更要把口径**写在曲线上**，
而不是让每个人自己猜。三种可能，选一个才能画：

- **A · 吞吐**：单位时间内完成的 case 数（timeline 里 `done` 的条数 / 天）。
  好算、有真数据；但它只说明「忙」，不说明「有用」。
- **B · 达成率**：已完成 / 已开始（`done` ÷ 全部非 unknown）。
  比 A 体面一点，但对「一条大 case 卡了三天」不敏感。
- **C · 周期**：从进队到终态的平均小时数（approvals `enqueued` → timeline 终态）。
  最接近「效率」，但需要 case 有始有终，现在很多 case 只有半截。

我的建议：**先画 A，把口径写成曲线下方一行小字**（「口径：timeline 每日 done 条数 · 未治理，仅供趋势参考」）；
同一张图上再叠 B 作为第二条线。等数据治理真跑起来，再换 C。
理由：A 现在就有真数据，画出来不会假；C 最准但现在的数据只能画出断线。

## 权限这层怎么落（这是必须先拍的）

看板现在**没有身份**：所有页面都当同一个人看，签的查询票主体是固定的 `board-ui`。
而这份口述里 1/3 的内容（成员、卡点、沉淀、审计）都以「谁能看什么」为前提。

三条路，取舍不同：

- **A · 身份先做真的**：看板登录（或从 ANС 网关注入身份）+ 后端按 subject 过滤 `/api/*`。
  地基对，十屏的权限规则都能真写；代价是这一轮只能改完 1–2 屏。
- **B · 先做角色切换器（框架）**：前端记住「我现在是超管 / 管理员 / 成员」，按角色隐藏页面与字段，
  后端不加鉴权。一天能看到全貌与交互，但这是演示，不是隔离 —— 谁都能切。
- **C · 这轮不做权限**：十屏框架先铺完，权限只写成页面上的规则文字，留到下一轮。

## 这轮不做

- 不画没有数据支撑的曲线（宁缺）；
- 不改客户侧的库（口径先落在看板这一层）；
- 不做第二套写口：装 / 审 / 接 这些动作，最终仍要落回 `anc` 的命令行语义。
