# 界面的四件事（按使用者原话拆）

2026-11-14 晚。这份只记**要做什么、为什么**，做完的划掉。

---

## 一、导航：能收、能放、能叉掉

**原话**：「左侧点开之后，这个项目它有一个可以叉掉的导航栏，在上面可以悬浮，我随时点回来。」

**已做**：
- 收起只留 56px 图标条；鼠标进入自动展开，**覆盖在内容上而不是推挤内容**
  （推挤会让版面每收放一次就重排）
- 组标题（「工作」「组织」「运行」）以前看起来像个能点的框，点了没反应 —— 现在只做分区标记

**待做**：
- 收起态下每个图标要有 tooltip（现在靠 `title`，够用但不精致）
- 键盘：`[` 收起/展开

## 二、别把系统暴露给业务人员

**原话**：「左侧栏目下面，校验干净、时间点、待批卡点 BOT 红这种东西……ANC 总览 时间线 只读观测这种东西……某车队 feishu Asia/Shanghai。」

**已做**：侧栏底部四块全部删掉（校验状态 / 三个计数器 / `ANC.BOARD.V3` / 三个脚链接）。
计数器挪回各页顶部——那里有上下文，读者知道这个「3」是什么的 3。

**待做**：
- 顶栏同样要清：`LIVE`、`校验干净`、「生成 20:19:51」都是调试 HUD。改成「截至 20:19」一处即可
- 「feishu · Asia/Shanghai」降到悬浮提示（已做），业务人员不需要看见部署细节

## 三、设置：角色到底是谁、能做什么

**原话**：「超管这里管理员责任是什么的啊？我们没有一个设置的团队吗？就是没有设置的界面吗？」

这句话是在指一个真问题：**顶栏那个下拉只是在演示权限，没有一处告诉人"这个角色能干什么"**。

**要建一页「设置 / 团队」**：

| 分区 | 内容 |
|---|---|
| 成员 | 谁在这家公司、什么角色、名下有哪几个 Agent、是否在线 |
| 角色 | 每个角色能看哪几页、能做什么动作（**直接读能力表，不另写一份**） |
| 身份 | 当前看板是"以谁的视角看"，以及为什么它不是登录 |
| 组织 | 公司名、语言、时区、平台绑定（这些是**配置**，不是首页装饰） |

关键：**角色说明不许手写**，必须从 `<vault>/capabilities.md` 现算。手写的那份三个月后一定和代码不一致。

## 四、把「路由与用量」接进来（最看重的一条）

**原话**：「最看重是他路由的能力……监控 token 用量、API 用量，同时监控不同 Agent 或不同人以及业务域的实时数据状态……要成为一个子页面，子页面里面又有好几个子页面。」

这是把 LLM 中转站那套**可观测性**搬到组织维度上。结构建议：

```
流量
├─ 总览        今日调用数 / token / 失败率 / 平均时延；按小时的热力
├─ 按 Agent    每个 agent 的调用量、成功率、最近一次活动、当前在跑什么
├─ 按人        谁触发的（含代谁）、用了多少、哪些是他的
├─ 按业务域    每个域的量、成本、跨域行使次数
└─ 明细        一条一条，可筛可搜，点开看这一次调用的上下文与结果
```

**必须先说清的前提**：我们现在**没有 token 计量**（议题 #12 未做）。所以第一版只能做
「调用数 / 动作数 / 成功率 / 时延 / 谁触发」，token 与成本要等计量接上。
**不能先画一个假的 token 曲线** —— 那正是我们一直在批的东西。

数据来源已经在手上：`audit`（每次行使一条）+ `trail`（聚合）+ `timeline`。
缺的是**按 agent / 人 / 域 / 小时的聚合接口**。

## 五、记录页：给人的，不是给工程师的

**原话**：「记录这里，你把每一步决策写成了类似一个 JSON 或者日志的东西……不是我们要展现给人类的形态。」

现在记录页把 case 展开成一条条流水（字段名 + 值），工程师看得懂，业务看不懂。

**要改成叙事**：

```
【Q3 结算改造】  卡在：等财务确认   ·   负责人：Bob   ·   已 6 天没动
  ├ 11-10  Alice 说：口径按合同附件三
  ├ 11-11  Bob 交了一批：附对账单（3 个文件）
  └ 11-12  系统：等财务确认 —— 卡在「谁有权确认」
```

原则：**人、动作、对象、结果**四样写进一句话；技术字段收进「详情」。
一行一条，不缩进成代码块。
