### 结论（按那份 prompt 的 A–F 分类）

| 类 | 有没有 | 证据 |
|---|---|---|
| A 契约漂移 | 无 | `core/types.ts` 逐条对得上真实 payload |
| B 结构反模式 | **有** | 16 处 `!important`；七份 CSS 互相覆盖 |
| C 类型不安全 | **有** | 42 处断言 |
| D 状态与异步 | 部分 | 弹回/重绘已修；抽屉状态不进 URL 仍在 |

## 二、「computer user」这个角色

你要的东西我先翻译成一句话：

> **给 Agent 一个正式身份，让它以"这台机器上的一个用户"的身份调 ANC 的接口**，
> 而不是借用人的账号、也不是看板里那些给眼睛看的 JSON。

它和现有三者的关系：

| 角色 | 是谁 | 现在怎么进来 |
|---|---|---|
| 成员 bot | 一个人 | 飞书 / 密码 |
| 业务 agent | 一个岗位 | `agents.md` + 任务队列 |
| **computer user**（新） | **一个运行在机器上的程序** | 待建：专用凭据 + 专用接口面 |

三件事它必须与"人"不同：

1. **凭据不是密码**：一把可撤销的机器令牌（`anc machine token`），带作用域与到期。
2. **接口面不是看板 JSON**：现有 `/api/*` 是给界面看的（字段多、为渲染组织）。
   给 Agent 的要**面向动作**：`task.pull`、`task.ack`、`context.get`、`audit.append`。
3. **留痕要能分开**：账上必须一眼看出"这次是机器干的"，不能和人的行使混在一起。

## 三、语言选型：FastAPI 还是留在 Go

你说用 FastAPI。按项目红线（不许默认语言，先写清语言+理由+代价），我把账摊开：

| | Go（与现有二进制同一个） | FastAPI（Python 独立服务） |
|---|---|---|
| 交付物 | **仍是单二进制**，零新运行时 | 多一个 Python 运行时 + 依赖树 |
| 部署 | 客户机器上放一个文件 | 要装 Python、装 venv、管进程 |
| 与权限/审计共用 | 直接复用 `org` / `audit` / `authz` | 要么重复实现，要么每次 HTTP 回调 ANC |
| 冷启动 | 毫秒 | 解释器启动 + import，需实测（不实测不许估） |
| Agent 生态熟悉度 | 中 | **高**（多数 agent 框架默认 Python） |
| MCP | 手写 JSON-RPC（我们已有 envelope 的 MCP 实现） | 有现成 SDK |

**我的判断**：在"只给 Agent 用"这个目标上，FastAPI 的收益是**生态熟悉度**，
代价是**把单二进制变成双运行时**——那是这个产品最核心的承诺之一（客户内网、一个文件、无依赖）。

折中方案（我建议）：**同一个 Go 二进制里加一层 `/agent/*` 的面向动作接口 + MCP 端点**，
权限与审计复用现成的；等真有客户要求 Python SDK 时，再写一个**薄的 FastAPI 适配器**
（只做协议转换、不碰业务、不碰凭据），那时它才是一个可选的壳，而不是系统的第二半。

**要你拍一句**：按 Go 走（我下一轮就能动手），还是坚持 FastAPI（我先给一版只有协议转换的薄壳，
业务仍落在 Go 里）？
