## 1. 这个产品押什么（唯一亮点）

### 押注

> **屏幕上每一个数字，都能点开，回指到产生它的那几行原始记录，并写明算它的口径。**

别的看板给你一个数；这个看板给你「这个数从哪来、怎么算的、什么时候算的」。
对一个卖**数据治理**的产品，这就是卖点本身 —— 客户最怕的不是没数，是**不敢信的**数。

### 为什么不是别的（都想过，都不押）

| 备选 | 为什么不押 |
|---|---|
| 权限隔离可视化 | 每家都宣称；而且没有真身份时，它只能是演示（B 方案的上限） |
| 数据流动动画 | 好看，不构成壁垒；**假动画比没有更糟**，真动画的数据源我们现在没有 |
| 18 屏大而全 | 用户记不住，我们也做不完；屏数不是价值 |

### 押注的代价（必须认）

每个上屏的数字都要付「合同 + 回源」的成本。所以：

- **这一版上屏的数字不超过 24 个**（含统计卡、曲线、表里的汇总列）；
- 超出预算的数字，只能以明细行出现（明细行不配合同，它自己就是原始记录）；
- 任何「先画上去回头再补口径」的曲线，一律不做。

### 怎么知道押对了（第 2 阶段结束就能看出来）

1. 演示时有人**主动去点**那个数字，并问「这行是哪来的」；
2. 客户侧的安全 / 审计角色对这一点有反应（而不是只问「能导出 Excel 吗」）。

两条都没有 → §1 押错了，停下来改押注，不继续往下铺。

## 3. 每屏的完成定义（DoD · 固定 6 条）

一屏只有六条全过才算做完，缺一条就是「没做完」而不是「差不多」：

1. **合同已写**：看什么 / 谁能看 / 数据从哪来 / 空态与读不到说什么 / 用哪条命令验
2. **真数据**：跑 `.devbox/macos/acme2`，不用假 fixture
3. **三态有人话**：空 / 读不到 / 无权限，各自说清「为什么」和「下一步找谁」
4. **三断点截图**：1440 / 1024 / 390
5. **键盘与控制台**：Tab 能到正文；控制台零报错
6. **门禁**：`dev/dev.sh all` 绿；无新增硬编码颜色；对比度 AA

## 4. 会被挡住的地方（风险登记）

| 风险 | 影响 | 现在的对策 |
|---|---|---|
| 后端没有鉴权 | 权限只能是演示，条目级过滤是前端假过滤 | 切换器上写「演示身份，未接鉴权」；把「真身份」列成独立议题，不假装做了 |
| 效率曲线数据太薄（现在 7 个 case） | 曲线可能只有几天点 | v0 只画「每日 done 条数 + 达成率」，点数太少就**不画曲线**、只给数 |
| 接入页没有写口 | 只能做只读框架 + dry-run 预览 | 阶段 5 先做「解析 + 预演」，真正落盘仍走 `anc` 命令行 |
| 我的上下文会耗尽 | 计划与判断丢失 | 三份文档自足：只读文档就能接上，不依赖聊天记录 |
| 越做越多 | 屏数膨胀，每屏都半成品 | `REQUEST-INBOX.md` 排队 + 每阶段一次「砍」评审 |

---

## 5. 砍的规则

每阶段结束问一次，三问：

1. 这一屏，有没有人在**没人要求**的情况下打开过？
2. 这一屏上的数字，有没有人点开看过来源？
3. 如果没有这一屏，谁会因此做错决定？

三问全是否 → 砍，并把结论写进 `DECISIONS.md`（砍过的不要再捡回来）。
