# 从 Hermes 学什么：一个"越用越顺手"的 agent，和一个"越用越顺"的公司

> 2026-11-19。起因：ANC 本身就是一个大 Agent / 一个超级 harness（见 SPEC §1.0.0 的飞轮），
> 而 Hermes 是当前把「闭环学习」做得最实的开源个人 agent。它的坑与解，和我们同构。

## 一、Hermes 的五个支柱，对我们各自的含义

Hermes 的架构常见说法是五根柱子：**memory / skills / soul / cron / self-improving loop**
（见 [Hermes Agent 拆解](https://www.eet-china.com/mp/a497696.html)、[闭环学习机制](https://raw.githubusercontent.com/QianJinGuo/wiki-public/refs/heads/main/entities/hermes-agent-closed-learning-loop.md)）。

| 支柱 | Hermes 的做法 | ANC 对应物 | 差距 |
|---|---|---|---|
| memory | 两个文件：`user.md`（你是谁、偏好、绝不要做）与 `memory.md`（环境、在办项目） | 真相源（company/members/domains）+ 上下文装配（ctxpack） | 我们有"组织记忆"，**没有"这个 agent 的偏好与禁忌"**，也没有保鲜 |
| skills | 具名技能，可自修补 | `skills/<name>/SKILL.md` + 经验对象（`internal/exp`） | 有对象，**没有"用起来效果如何"的信号** |
| soul | 人格设定 | persona / roles | 个人 agent 需要，**公司不需要**（见第四节） |
| cron | 定时主动做事 | `anc job` | 定时器有，**"每天自动摇一次飞轮"没接** |
| learning loop | 触发 → 异步 review → 提炼 → 写回 → 再注入 | 我们的六步飞轮（捕获→归一→评级→提炼→部署→回流） | **只有捕获是自动的，后面五步都要人推** |

## 二、值得直接学的六条机制

### 1. 记忆要分两份，而且"陈旧记忆是头号故障"

Hermes 把「你是谁」和「环境现在什么样」分开存，两者生命周期不同；
社区里反复提到的一句话是：**agent 行为变怪，第一嫌疑是记忆过期**。

ANC 现在只有一份组织事实，没有"这条事实多久没更新"的可见信号。
`METRICS.md` 想过口径，但**没有落地成字段**。

**该学**。第一步：给关键条目加 `as_of`，页面上超过阈值标黄（不是删除，是提醒）。

### 2. 蒸馏由**触发条件**发起，不是由"盘点"发起

Hermes 的触发阈值是显式的：**一次任务 5 次以上工具调用、从错误里恢复、或被用户纠正**，
就把轨迹蒸馏成一个具名技能。不是"感觉该总结了"。

ANC 的蒸馏现在是 `anc distill`：**只读、现算、手动跑**（`distill.go` 自述"不写 skills/"）。

**该学，而且这是当前最该补的一环**。我们已经有全部原料（audit/timeline/blockers），
缺的只是"什么时候该蒸馏"的阈值 —— 而我们连 `blockers` 里的 `kind` 都存好了。

### 3. review 跑在后台，不阻塞主对话

Hermes 的 review 是异步的：主对话不等它。

ANC 有 `anc job`（定时器），但**没有把"蒸馏/评级"挂上去**。
结果就是"托管 = 中心机每天自动摇"这句写在 README 里，链却没接（我们自己也承认了）。

### 4. 技能会自修补，也能被离线重写

Hermes 的技能在使用中被字符串补丁修订；表现差的技能可由离线流程（GEPA）从执行轨迹重写。

ANC 的经验对象有 `version` 与 `digest`，**没有效果信号** —— 所以"哪条经验没用"答不出来，
飞轮第⑥步（回流）目前是空的。

**该学**。第一步：给经验加 `reused_count`，从"被引用"事件里数，不靠人填。

### 5. 压缩产生**血缘**，而不是重写历史

harness 层的这句设计原则（见 [Arize 的 Hermes harness 拆解](https://arize.com/blog/how-hermes-implements-open-source-agent-harness-architecture/)）
和我们已经在做的是同一条：**`derived_from` + 更正只追加 + `ScanGovernance`**（SPEC §14.2 N/T）。

这条不用学，**是互相印证**：我们的 N/T 两类对象方向是对的。

### 6. 多个入口共享**同一个会话面**

CLI、聊天平台、定时任务读写同一份 session；每个入口各存一份就是漂移的开始。

ANC 的热层（`internal/hot`）已经是这个角色：`anc task` / 看板 / 定时作业都读它。
**这条我们做对了，继续保持。**

## 三、不该学的三条

1. **soul / 人格**：个人 agent 需要"像你"，公司需要"可替换"。ANC 的 persona 是岗位的，不是人格的。
2. **技能自动改写正文**：Hermes 允许技能自修补；我们的判据 7 规定**经验未经人确认不得部署**。
   这条不放开 —— 自动改写对话口径，等于让公司规则自己漂移。
3. **无审核的自动写记忆**：我们有 `role` 归因与更正机制（判据 4/13），
   自动写入必须带出处，否则等于把猜测当事实。

## 四、落到 ANC 的改造清单（按性价比排序）

| # | 改造 | 为什么先它 | 验收 |
|---|---|---|---|
| 1 | **触发式蒸馏**：把 `blockers`（同类 ≥N 次 / 有可复用突破）自动变成经验候选 | 原料已全，只差阈值；一次接上飞轮下半圈就转了 | 给定 N，跑一次能产出候选，且每条带证据链 |
| 2 | **异步 review 作业**：把 1 挂到 `anc job`，每天摇一次 | README 承诺"托管=每天自动摇"，现在没接 | 次日能查到作业跑过、产出可审 |
| 3 | **记忆保鲜**：关键条目加 `as_of`，超阈值标黄 | 陈旧记忆是头号故障，我们连预警都没有 | 页面上能看到"这条多久没更新" |
| 4 | **效果回流**：经验 `reused_count` + 同类卡点数量月环比 | 没有它，"经验有没有用"永远是猜 | 月报能给出两组数字 |
| 5 | 技能自修补（只生成补丁建议，不自动应用） | 判据 7 不允许自动生效 | 建议进入待批，人点了才写 |

**判据**：学 Hermes 的标准不是"像它"，而是**我们这一圈的转速有没有变快**。
每做一条，都要能回答：它让哪一环从"人推"变成"自己转"。

## 五、与治理层的关系

Hermes 的闭环 = 我们的飞轮；它的"记忆两文件" = 我们的上下文装配；它的"技能自修补" = 我们的经验对象。
**同一件事的两种规模**：一个 agent 的自我改进，与一家公司的自我改进。

差别只有一条，而且是我们不能丢的那条：
**个人 agent 可以自己改自己，公司不行 —— 改公司行为的东西必须有人签字。**
