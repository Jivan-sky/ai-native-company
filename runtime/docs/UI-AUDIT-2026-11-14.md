# 前端面板梳理（用 ego lite 真跑一遍）

2026-11-14 · 用 ego-browser 在真浏览器里走完 9 页，逐项对照后端返回。
**为什么必须这么查**：后端每条 API 都对、每个字段都有出处，但页面照样能给出错误印象 ——
这类问题只有把页面真跑起来才看得见。

## 一、查出来的（按严重度）

### F1 · `LIVE` 徽标是装饰品 —— **已修**

| 事实 | 证据 |
|---|---|
| 页面从不重取数据 | 打开后再等 15 秒，`/api/*` 请求数增量 **0** |
| 「生成」时间冻住 | 一直停在打开那一刻 |
| 但页头亮着 `LIVE` | `shell.ts` 里 `live = d && d.board ? … "LIVE"` —— 只要拿到过数据就亮 |

**为什么后端看不出来**：`curl /api/approvals` 每次都是新鲜的，`/api/board` 的
`generated_at` 每 3 秒推进一次。后端没问题，是前端只取一次还挂着"实时"的招牌。

修法（`app.ts` + `shell.ts`）：

- 30 秒轮询，`document.hidden` 时停（没人看就不该有后台流量）
- 输入框有焦点时不刷（重渲染会吞掉正在打的字）
- 徽标说实话：60 秒内取到过才叫 `LIVE`，否则降级成 `快照` + 悬浮说明上次更新时间

修完实测：35 秒内 13 次 `/api/*` 请求（一轮刷新 = 13 个端点），生成时间 19:28:26 → 19:28:56。

### F2 · 页面标题写成了一整段解释 —— 未修

h1 的位置上放的是设计说明，不是"这是什么页"：

| 页面 | 现在的标题 |
|---|---|
| 系统 | `gateway判活 = 真拨一次 socket，不看文件在不在（残留文件会把「挂了」看成「在跑」）` |
| 组织 | `我的卡片看板不做登录：这里只决定「以谁的视角看」，不改任何权限` |
| 项目 | `全部项目在跑的在上；周期过了不等于做完了` |
| 记录 | `三档` |

**后果**：浏览器标签页标题、读屏器的页面标题、跳到内容后的第一句 —— 都是这段话。
"我在哪一页"反而要往下看才知道。

建议：`h1` 用页名（系统 / 组织 / 项目 / 记录），长句降级成 `h1` 下面的第一段说明。
这 9 页是同一处模板，改一次就够。

### F3 · 部分页面没有 `h1` —— 未修

`#/run`（含四个子标签）、`#/approvals` 里正文标题用的是 `h2`，全页没有 `h1`。

发现过程本身就是证据：我第一版巡检脚本按 `main h1` 取标题，
在这几页拿到 `null`，差点把"页面正常"误判成"页面空白"——
**读屏器和跳转工具取页面标题走的是同一条路**。

建议：与 F2 一起改 —— 每个页面恰好一个 `h1`，子标签用 `h2`。

## 二、查了但不是问题的

| 怀疑 | 结论 |
|---|---|
| `#/run?tab=jobs` 空白 | 不是。子标签按 URL 正常工作（作业 3 个 / 已接入 3 条 / 注册表 2 条），是我脚本取 `h1` 取不到 |
| 待批页说"热层没接上" | 不是产品问题。是我起服务的姿势：旧的 board 进程占着 8710 且没带 `--hot-addr`，新进程 bind 失败；redis 容器也没发布端口。拉起来后 `wired: true` |
