## 三、怎么落地：把验收表抄成测试

那份文档最值钱的不是结论，是**每一条都有「最小事件顺序 + 应看到的结果」**（A1-1 … C2-9 共 40 多个反例）。

落法固定：

1. 每个反例先写成一条**会失败的测试**（表驱动，照抄文档里的三列）。
2. 测试绿了再改实现 —— 绿的测试是「修好了」的唯一定义。
3. 复现不出来的，在 issue 里注明「静态推断不成立」并关掉，不硬修。

这比读代码猜要快，也避免修出「文档说对了但其实没这个 bug」的假修复。

## 四之二、A1 已复现并修掉（2026-11-14）

审计的四条指控，**逐条对着代码核过**，全部成立：

| 指控 | 代码里是什么 | 判定 |
|---|---|---|
| 同 case 的普通记录算「已归档」 | `settledEntry` 用 `Case == id \|\| ID == "task-"+id` 匹配 | ✅ 成立 |
| 检查前就删热层并返回 Already | `already` 分支在 stage 检查**之前** `st.Drop(id)` | ✅ 成立 |
| 按 ID 无条件删，抹掉中途的交接 | `Drop(id)` 不看版本 | ✅ 成立 |
| 无 `expected_version`，旧请求判不出过期 | `Opts` 里没有这个字段 | ✅ 成立 |

**最硬的一条证据**（红灯测试）：

```
--- FAIL: TestSettleIgnoresSameCaseNote
    进行中的任务要报「还没结束」，得到 <nil>
```

也就是说：写一条同案进度备注，再跑普通结账 —— **结账成功了，还在跑的任务被从热层删了**。备注把活干掉了。

修法（`internal/tasksettle`）：
1. `settledEntry` **只认结账行自己的身份** `task-<id>`，不认「同 case 的任何一行」。
2. `Opts.ExpectedVersion`：给 0 = 不校验（兼容旧客户端）；给了就比对，不一致返回 `ErrStale` 并带上当前版本。
3. `Store` 接口把 `Drop` 换成 `DropCAS(id, version)`：热层用 Lua 做**原子**的「版本对得上才删」。
4. 落库后才发现版本变了 → 终态行保留（事实不能撤），但**不清热层**，并如实报错。

新增三条验收测试（A1-1/A1-2 与「落库后才发现版本变了」），全部红转绿。

## 四之三、A2 已复现并修掉（2026-11-14）

指控「两位操作者都可能先读到待批、各自成功写下相反决定」——**并发测试直接打出来了**：

| 代码状态 | 结果 |
|---|---|
| 修之前（无唯一回执） | `第 0 轮：时间线该只有 1 条裁决行，拿到 2` |
| 修之后 | 40 轮并发，每轮恰好 1 条时间线、1 条审计、1 个成功者 |

修法（`internal/approvals`）：

1. **唯一裁决回执**：`<vault>/decisions/<proposal_id>.json`，用 `O_EXCL` 创建。
   它先于两本流水 —— 两个人都读到待批、都想裁时，只有一个人能创建成功；
   另一个拿到 `EEXIST`，转去读那份回执。于是「两个相反决定都成功」在物理上不可能。
2. **回执自带提案快照**：即使队列已经清掉，重投也能凭它把漏掉的投影补齐。
3. **投影幂等**：按稳定 ID（`approval-<id>-<signal>`）查重，重投只补缺的那本，不新增。
4. **顺序改成 回执 → 投影 → 清队**。原来「清队」在最后，靠「队列没了」防重；
   现在防重靠回执，队列只是状态的镜像。
5. **同参重投**返回原裁决（`Already`），**换信号 / 换人**返回 `ErrConflict` —— 两种都叫"重投"，
   但一个该放行、一个该拒绝，不能混成一个错误。
6. HTTP 层仍返回 409（旧看板靠它判「这一轮结束了」），但把原裁决与原操作者一并给它。

改了 1 处既有断言（已说明）：`TestSettleWritesBothAndClearsQueue` 原来断言「重复点头报 ErrNotQueued」，
现在断言「幂等返回原裁决 + 不新增行」——后者更强（多了 `Already` 与原裁决的一致性的检查）。
