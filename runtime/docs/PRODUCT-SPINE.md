# 产品的脊柱

> 一页。写的是「这东西靠什么成立」，不是「我们做了什么」。
> 任何一页界面，如果答不出这里的某一问，它就不该存在。

## 一、三类人，三个"每天第一个问题"

| 人 | 打开它时心里那句话 | 界面必须几秒内答出来 |
|---|---|---|
| 一号位 | 「今天有没有事要我做？」 | 有事 / 没事；有事的话，**第一条是什么、点哪儿处理** |
| 业务负责人 | 「我这摊谁在跑，卡在哪？」 | 我的人、我的活、卡住的那几件 |
| 一线 | 「这活下一步归谁？」 | 我手上有什么、交给谁、凭什么 |

**判据**：这三句话答不出来，页面再漂亮也是零。

## 二、三条回路（产品只做这三条）

### 回路一 · 决策
`有人提请 → 我看到 → 我点头/驳回 → 留痕 → 下一个人收到`

- 今天断在哪：提请教不了、身份靠手打、"该我批"没有分拣。
- 做完的标志：**一次审批不用离开这一页，不用看英文 slug。**

### 回路二 · 追溯
`一个数字 → 它是怎么算的 → 谁定义的口径 → 原始记录在哪`

- 今天断在哪：口径写死在代码里（`done ÷ (done+failed)`），等于替客户定义业务。
- 做完的标志：**每个数字旁边都能点开「谁定义的、按什么算」，且客户能改。**

### 回路三 · 追问
`出事了 → 问它一句 → 它知道我在看哪一页、知道这块的上下文 → 答人话`

- 今天断在哪：对话不带上文页，未接模型时回一串 JSON 报错。
- 做完的标志：**问「这个卡点谁负责」，它答的是这一页上那个人，不是一段日志。**

## 三、每页只干一件事

| 页 | 唯一职责 | 不合格的样子 |
|---|---|---|
| 总览 | 答"要不要我动手"，并给第一条动作 | 摆一堆计数让人自己找 |
| 待批 | 让一次决定**当场做完** | 空房间 + 一个输入框 |
| 项目 | 20 个项目一屏可比 | 卡片流，滚 10 屏 |
| 组织 | 谁负责什么、卡点在哪 | 名片墙 |
| 运行 | 什么在跑、上次成没成、现在能不能起 | 讲 socket 与路径 |
| 数据 | 有哪些数据、谁能看哪一列 | 讲表结构 |
| 记录 | 一件事的来龙去脉，**用人话** | 把流水当 JSON 铺开 |
| 资产 | 哪些料能沉淀、还差什么 | 只报数量 |
| 系统 | 出故障时能不能一眼定位、一键修 | 诊断书，没有动作 |
| 设置 | 谁能看什么，以及**我为什么看到这些** | 只有一张表 |

## 四、产品力的三个硬判据

1. **30 秒能完成一件事**（不是"能看到一件事"）。
2. **出问题能追到人**：谁批的、按哪条授权、原文在哪一行。
3. **新人不必问人**：他要的上下文、权限、工具，界面上就有。

这三条现在是**部分成立**：追溯有底子（审计双流水 + 行级 src），决策和新人这两条基本没有。

## 五、先不做什么

- 不做多语言、不做主题定制 —— 还没到那一步。
- 不做移动端 —— 使用者是坐在电脑前的负责人。
- 不做"更好看"，做"更少东西"：每加一个元素，先问它答的是上面哪一问。

## 六、怎么保证不倒退

`dev/ui-invariants.mjs` 用真浏览器跑 10 页，把过去两周被指出的每个错变成一条断言：
h1 唯一、无本机路径、侧栏宽度跨页保持、轮询不重建 DOM、顶栏无调试 HUD。

**改完不跑它，等于没改。** 这是这两周最贵的教训：问题都是使用者发现的，因为我从没自动验证过。
